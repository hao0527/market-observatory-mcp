# 1.6.0 历史稳定性与归档验收

## 修改与必要性

本轮优先修复主源部分数据提前返回、分钟长范围重复请求、永久历史与14天故障缓存混用、覆盖率和字段完整度混用。增加现有D1内的可配置观察列表、原始采集/已完成none历史、可恢复分日补采，未增加分析或新行情指标。没有充分证据的停牌、上市边界、固定保留期限和复权因子版本继续标为未核实。

| 原问题 | 修复后 |
| --- | --- |
| 主源partial就提前结束 | 尝试完整备用区间，按覆盖选择单一提供方；未选备用也保留尝试和错误 |
| 按周重复读取同一保留窗口 | 有边界的整段读取、至多一次同源窗口恢复；补采任务精确到日 |
| 历史依赖14天缓存 | 同一DB新增不自动过期归档和原始证据，与原缓存隔离 |
| 240根但amount=null被看作缺K线 | bar_coverage与field_completeness独立；不估算成交额 |
| 完整缓存刷新失败状态矛盾 | 数据质量独立于刷新结果，degraded/error单独保留；别名一致 |
| 缺失日期无法追踪 | 逐日缺失标签、连续缺失区间、原始请求、拒绝原因和退避重试 |
